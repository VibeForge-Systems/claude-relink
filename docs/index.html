Claude Code session recovery · v1.0.0 · Apache-2.0

claude-relink

Recovers Claude Code conversations orphaned by a moved project directory. Transcripts, subagent transcripts, project memory, settings and prompt history are moved or merged to the directory's new home, with every absolute path inside rewritten.

single filePython 3.8+standard library onlydry run by defaultbackup and undo on every applyreads Windows-origin stores
Mechanism

Why sessions vanish when a directory moves

Claude Code files every project under a slug derived from its absolute path: each character that is not a letter or digit becomes a hyphen. The slug is the only link between a directory and its sessions. Move the directory and claude --resume looks under a slug that holds nothing. The transcripts are intact. They are filed under a path that no longer exists.

Previous location
/home/dev/src/personal/ledger-api
re.sub(r'[^a-zA-Z0-9]', '-', cwd)
~/.claude/projects/-home-dev-src-personal-ledger-api/
Nine sessions, project memory and settings. Present on disk, unreachable from the new directory.
Current location
/home/dev/src/acme/ledger-api
same rule, different path
~/.claude/projects/-home-dev-src-acme-ledger-api/
What /resume lists: only sessions started after the move.

The same mechanism separates one project across machines and spellings. A copied ~/.claude from a Windows workstation holds D:\src\ledger-api, D:/src/ledger-api and d:/src/ledger-api as three config entries for one directory, each produced by a different way of launching Claude Code.

Scope

What a project store contains

Verified against Claude Code 2.1.x by reading the binary and real stores. Everything keyed by session id is left alone. Everything keyed by path is moved and rewritten.

ItemCarries pathsHandling
<sessionId>.jsonl transcriptsyescwd on every record, tool inputs (file_path, command), toolUseResult.filePath, file-history snapshot keys. Moved and rewritten line by line. Untouched lines stay byte-identical; mtimes are preserved so the resume picker's order is unchanged.
<sessionId>/subagents/agent-*.jsonlyesMoved and rewritten.
<sessionId>/tool-results/, workflows/opaque outputMoved as-is.
memory/MEMORY.md, memory/*.mdoftenMoved and rewritten. On merge the target's index is kept; the previous index is saved as MEMORY.imported-from-<slug>.md and linked from it, so the size-capped index never grows past its limit.
sessions-index.jsonyesfullPath and projectPath rewritten; entries merged into the target's index.
~/.claude.json → projects[<cwd>]the keyAll spellings of the previous path merged into projects[<new cwd>]: allow-lists unioned, MCP servers merged with the target winning on conflict, trust OR'd, counters maxed.
~/.claude/history.jsonlyesproject re-pointed. On import, source entries are appended and deduplicated.
file-history/, todos/, session-env/session id onlyUntouched.
<project>/.claude/settings.local.json, .mcp.jsonsometimesMoved with the directory but may still read Read(/old/path/**). Reported; rewritten with --rewrite-project-files.
Commands

Operating sequence

Nothing is modified without --apply. Every apply writes a full backup first and prints the undo command.

01

Scan — what is orphaned, and where it went

Read-only. Lists every store whose recorded directory no longer exists, its sessions, and ranked candidates for the new location found under the search roots.

claude-relink scan --search-root ~/src
Claude Code store : /home/dev/.claude Project stores : 23 (18 connected, 5 orphaned, 0 undeterminable) Candidate dirs : 61 under /home/dev/src (depth 2) ORPHANED /home/dev/src/personal/ledger-api store : /home/dev/.claude/projects/-home-dev-src-personal-ledger-api sessions : 9 (31.4MB, last activity 2026-09-02 14:11) extras: memory, sessions-index.json repos : acme/ledger-api (27) - 4e12ae05 2026-09-02 14:11 12.2MB Migrate settlement batch to event sourcing - e645dc69 2026-08-30 09:40 4.1MB Idempotency keys for the payouts endpoint candidates: [HIGH 0.96] /home/dev/src/acme/ledger-api - same directory name - 212/240 files referenced in transcripts exist here (88%) - git remote matches transcripts (acme/ledger-api) - already a Claude project (merge target) relink : claude-relink relink --from /home/dev/src/personal/ledger-api --to /home/dev/src/acme/ledger-api --apply

Without --search-root the candidate pool is the projects Claude already knows about, which is sufficient once Claude has been opened in the new location. --all also lists healthy stores; --json gives machine-readable output.

02

Relink — dry run, then apply

Prints the full plan and changes nothing. --from accepts the previous path in any spelling, the slug, or a unique substring. Mode is chosen automatically: move when no store exists for the new path yet; merge when sessions have already been started there.

claude-relink relink --from personal/ledger-api --to ~/src/acme/ledger-api claude-relink relink --from personal/ledger-api --to ~/src/acme/ledger-api --apply
Relink plan [MERGE] from : /home/dev/src/personal/ledger-api to : /home/dev/src/acme/ledger-api sessions: 9 to merge, 0 duplicates skipped, 0 conflicts path rewrite: all [ merge-session] 4e12ae05-8b80-4e3b-8237-5b8a5c7e8855 (12.2MB, 2026-09-02 14:11) Migrate settlement batch… [ sidecar] 4e12ae05-8b80-4e3b-8237-5b8a5c7e8855/ (subagents, tool-results …) [ memory] memory/MEMORY.md differs: previous index saved as MEMORY.imported-from-….md and linked [ index] sessions-index.json entries rewritten and merged into target index [ config] .claude.json: merge ['…/personal/ledger-api'] -> projects['…/acme/ledger-api'] [ history] history.jsonl: 143 prompt entries re-pointed [ remove-dir] remove emptied source store Applied: 9 sessions, 6,208 transcript lines rewritten, 41 sidecar files, 7 memory files, 143 history entries. Backup: /home/dev/.claude/backups/claude-relink/20261031-104210-… Undo : claude-relink undo --backup 20261031-104210-… --apply

Then cd into the new directory and claude --resume. The previous conversations are listed with the new ones, and a resumed session sees the new absolute paths throughout rather than attempting to read files at the old location.

03

Batch — every orphan with one unambiguous match

Relinks each orphan that has exactly one candidate at or above the threshold and no runner-up within 0.1 of it. Everything else is skipped with a reason, for an explicit --from / --to.

claude-relink relink --auto --search-root ~/src --min-confidence 0.8 # dry run claude-relink relink --auto --search-root ~/src --min-confidence 0.8 --apply
04

Import — from a copied ~/.claude on another machine

The source is never modified. Windows roots match case-insensitively with either separator, and sub-path separators are converted: D:\src\ledger-api\api\routes.ts becomes …/ledger-api/api/routes.ts. The matching .claude.json is found beside the copied directory or given with --src-config. Its project entry, in all spellings, is merged into the live config, and its history entries for that project are appended and deduplicated.

claude-relink relink \ --src-claude-dir /mnt/backup/laptop/.claude \ --from 'D:/src/ledger-api' \ --to ~/src/acme/ledger-api

For an inventory of a copied store: scan --claude-dir /mnt/backup/laptop/.claude --config /mnt/backup/laptop/.claude.json --search-root ~/src.

05

Undo

Each apply writes ~/.claude/backups/claude-relink/<timestamp>-<slug>/: a tarball of every store directory it changed, copies of .claude.json and history.jsonl, and a manifest. Undo restores exactly that prior state.

claude-relink undo # list backups claude-relink undo --backup 20261031-104210-… --apply
06

Dedupe — config spellings

Claude Code creates separate .claude.json entries for D:\src\x, D:/src/x and d:/src/x depending on how it was launched. This merges them; the entry whose directory exists is kept as the canonical key.

claude-relink dedupe # dry run; --apply to merge
Matching

How a candidate earns its score

Three independent signals, capped at 1.0. A name match alone never qualifies for --auto; the fingerprint is what separates a project from a fork or a backup copy of it.

Directory name matches
0.45
Deeper trailing components also match
up to 0.15
Files the transcripts touched exist under the candidate
0.5 × coverage
Git remote matches pr-link records or GitHub URLs
0.3 owner/repo · 0.15 name only
HIGH ≥ 0.80 — eligible for --auto MED ≥ 0.50 — suggested command printed LOW — shown for reference

The fingerprint is built from up to 400 distinct file paths found in Read, Edit, Write and Grep inputs and tool results across the orphan's transcripts and subagents, relative to the previous root. A move between GitHub organizations scores "name only" on the remote until the clone's origin is updated.

Safety

Guard rails and limits

Before every applyExit all Claude Code sessions. Claude Code rewrites .claude.json on exit and would clobber the merge. The tool refuses to run while a live process is registered in ~/.claude/sessions/; --force overrides.

What it guarantees

  • Dry run unless --apply; a backup and an undo command on every apply.
  • Boundary-aware rewriting: /src/proj never matches /src/proj2 or /src/proj.bak, but does match /src/proj/…, a sentence-ending /src/proj. and Read(/src/proj/**).
  • Lines that do not mention the previous path are copied byte-for-byte; a truncated final line from a crash is copied untouched.
  • Transcript mtimes preserved; identical duplicate sessions skipped; a conflicting session id keeps the target's copy and leaves the source copy in the backup.
  • Validated on a 2.7 MB Windows-origin transcript: zero leftovers, zero unparsable lines, and undo restored a byte-identical file.

What it does not do

  • Slugs longer than 200 characters receive a hash suffix in Claude Code that cannot be reproduced; those paths are refused rather than guessed.
  • Worktree sessions (<project>/.claude/worktrees/<name>) appear as their own orphans; relink them explicitly to the new worktree path.
  • tool-results/ files are copied verbatim. They are saved output, not parsed on resume.
  • Linux and macOS hosts. Reading Windows-origin stores is supported; running on Windows is untested.
  • Claude Code's on-disk format is undocumented and may change. scan is read-only and is the safe first check against a newer version.
